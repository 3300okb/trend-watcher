# project-baseline.md — 共通品質・セキュリティ基準

## 目的
- `~/.codex/AGENTS.md`（グローバル指示）が存在しない環境でも、
  このプロジェクト内のルールだけで最低限の品質・セキュリティを担保できるようにする。

## 基本方針
- 変更前に対象ファイルを必ず読み、既存スタイル（命名・構成・非同期スタイル）に合わせる。
- 実装後はビルドを実行して動作を確認する（`npm run build`）。
- lint・テストは**未導入**。未導入の項目は「未導入」と明記し、代替の検証（ビルド、対象スクリプトの実行）を必ず行う。
- マジックナンバーはファイル上部で定数化する（`const REQUEST_TIMEOUT_MS = 20000;`）。
- エラーハンドリングを省略しない。バッチはソース単位で `try/catch` し、1 ソースの失敗で全体を止めない。
- このプロジェクトは TypeScript 未使用（バニラ JS / ESM）。型注釈は不要だが、引数・戻り値の意味が曖昧な箇所は命名・コメントで補う。

## セキュリティ
- `.env` ファイルをコミット・ステージングしない。
- API キー・トークン・認証情報をコード / ログ / コンソールに出力しない。
- `public/assets/supabase-config.js` の anon key は公開前提（RLS で保護）。それ以外の秘密情報を追加しない。
- フロントエンドで HTML を直接挿入する操作（`innerHTML` 相当）は XSS リスクに注意する。

> 上記のうち機械的に強制できるもの（`.env` のコミット禁止・`public/data/` 直書き禁止・`out/` の add 禁止）は
> rules（`.codex/rules/`）と hooks（`.codex/hooks/guard.sh`）でも強制する。
